# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A navigable three.js model of ESO's La Silla Observatory (Chile). The app is two files with no build step, no package manager and no tests:

- `index.html` — all markup, CSS and one inline ES module (~700 lines). three.js r170 and `OrbitControls` come from jsDelivr via an import map, so the page needs internet.
- `data.js` — generated; a classic script that sets `window.LASILLA`. Do not hand-edit, and do not Read it whole (890 KB, mostly base64).
- `sky.js` — generated; sets `window.LASILLA_SKY` (catalogue stars, galaxies and constellation lines). Same rules as `data.js`.
- `zarathustra.mp3` — the Music button's track (Strauss, *Also sprach Zarathustra* introduction, Kevin MacLeod, CC BY 3.0; Commons' MP3 transcode of `Also Sprach Zarathustra - Einleitung.ogg`). `setMusic` creates the `Audio` lazily on the first click or `M`, because browsers block sound without a user gesture; a capture-phase `pointerup`/`keydown` listener starts it on the first interaction (retrying if the browser refuses), and never again once the user has used the button.
- `manifest.webmanifest` + `icons/` — makes the page installable as a home-screen web app (Android: manifest with 192/512 px icons and a maskable 512; iOS: `apple-touch-icon` 180 px and the `apple-mobile-web-app-*` metas in `index.html`). All paths are relative, so it works under the Pages sub-path. There is no service worker, so no offline use (three.js comes from a CDN anyway). Icons, `docs/preview.jpg` and `docs/app-wide.jpg` are all cut from one title image (1365×768, not in the repo): icons are the square at (642, 210)–(1200, 768); the maskable one is the larger square (590, 108)–(1250, 768) with the title corner patched over by mirrored sky.
- `tools/build_data.py` — regenerates `data.js`; `tools/cache/` holds its downloaded inputs.
- `tools/build_sky.py` — regenerates `sky.js` (standard library only). Its raw catalogues (HYG, OpenNGC; ~38 MB) are downloaded to `tools/cache/` on first run and are git-ignored.

## Running and checking

```sh
python3 -m http.server 8377 --bind 127.0.0.1   # then open http://127.0.0.1:8377/
node --check <extracted module>.mjs             # only syntax check available: copy the <script type="module"> body to a .mjs file first
```

Opening `index.html` via `file://` is designed to work (data is a classic script precisely so no `fetch` is needed) but has not been verified.

URL hash flags, combinable: `#day` (the page opens at night by default), `#still` (auto-orbit is on by default; use `#still` for screenshots and automation), `#meadow` / `#desert` (glacier is the default surface), `#clouds` / `#rain` / `#snow` / `#fog`, `#mute` (the music otherwise starts with the first click, tap or key press — use `#mute` for automation that clicks).

### Driving it from browser automation

`requestAnimationFrame` does not fire in a hidden or occluded tab, so the scene freezes (even initialisation waits for the first frame — take one screenshot after navigating before touching `window.app`) and CSS transitions (including the loading overlay fade) stall. Step it by hand through the debug handle instead of waiting:

```js
document.getElementById('loading').style.display = 'none';
app.setNight(true); for (let i = 0; i < 30; i++) app.tick(0.1);   // day/night fade takes 2.4 s of simulated time
app.camera.position.set(x, y, z); app.controls.target.set(x, y, z); app.tick(0.05);
```

`window.app` exposes `tick, setNight, setSurface, setWeather(kind, on), setRotate, flyTo, stargaze, setFollow, setMusic, goTo(clientX, clientY), cars, groundAt, sites, scene, camera, controls, renderer, THREE`. It is only defined after the terrain has been built (a second or two after load); do not `await` timers in the automation call — they may never resolve in a hidden tab.

## Coordinates and data

- Scene units are metres: **x = east, z = south, y = elevation − 2300** (`Y0`). Origin is `lat0/lon0` in `data.js` (−29.2562, −70.7362), roughly mid-ridge.
- `LASILLA.inner` / `.outer`: elevation grids as base64 little-endian Uint16 in decimetres, row 0 = north. Inner is 400² at 16.67 m (zoom-13 Terrarium tiles), outer is 400² at 133 m (zoom 10). `ox/oz` are the scene coordinates of cell (0,0).
- `LASILLA.buildings`: OSM footprints as `[x, z]` rings with `name`, `alt`, `kind`, `mm` (man_made tag). `LASILLA.roads`: polylines with `k` = OSM highway type. `LASILLA.nodes`: telescope point features.
- `data.js` is generated by `python3 tools/build_data.py` (numpy + Pillow; optional argument = alternative output path). It combines an Overpass query (telescopes, buildings, roads in a fixed bbox) with Terrarium elevation tiles, projected with Web-Mercator scaled by cos(lat0). Inputs are cached in `tools/cache/`; the committed cache reproduces the current `data.js` byte for byte, so check a change to the script with `python3 tools/build_data.py /tmp/x.js && cmp /tmp/x.js data.js`. Deleting `tools/cache/osm.json` refetches live OSM data, which can rename or add features that `SPEC` in `index.html` matches by exact name. The script downloads with `curl` because this machine's python.org Python fails TLS verification in `urllib`; `overpass-api.de` has returned 406 while `overpass.kumi.systems` worked.

## Architecture (the parts that span sections)

**Height pipeline.** `rawH` (bicubic SRTM, inner blended into outer at 2.3–3.1 km, plus small procedural detail) → `roadH` (drivable roads cut a bench into the slope using a spatial hash of resampled centre-line points) → `finalH` (circular flat platforms under every building, largest first so small neighbours adopt the big one's level). `finalH` is evaluated once per vertex of a non-uniform grid (`coords`: 6 m cells within ±1 km, growing 7 % per cell out to 26 km). After that, **use `groundAt(x, z)`** for anything that must sit on the rendered surface (camera clamp, viewpoints) — it reproduces the mesh's exact triangle interpolation. Platform heights are stored as `f.base` on each footprint.

**Ground appearance** is three layers on one `MeshStandardMaterial`: per-vertex colour (slope/noise based), a tiling multiply detail texture, and a 4096² canvas "site texture" covering ±1024 m around `SITE` that paints roads and gravel aprons, mixed in through `onBeforeCompile`. Roads are therefore texture, not geometry. `SURFACES` defines meadow/desert/glacier; `setSurface` swaps the colour attribute, detail texture, roughness and hemisphere ground colour, building each variant lazily and caching it in `terrain`.

**Buildings.** `buildObservatory` walks the OSM footprints: names found in `SPEC` become telescopes (`makeDome`, `makeNTT`, `makeDish`), everything else is an extruded footprint. Round footprints become a dome on a drum; rectangular ones get the extruded building with a dome on top. Entries with a `label` are pushed to `sites`, which drives both the HTML labels and the side list. To add or retitle a telescope, edit `SPEC` keyed by the exact OSM name. A `wiki` field (English Wikipedia article title) adds a link in the list; set it only for telescopes with their own article — several titles merely redirect to the La Silla Observatory page, so check with the MediaWiki API (`action=query&redirects=1&titles=…`) before adding one.

**Moving parts.** `spinners` holds the SEST dish head and the ESO 3.6 m dome shell (`userData.head` of `makeDish` / `makeDome`); `tick` turns them once per 10 s. `buildCars` builds a node graph from the drivable roads (`ROADW` kinds, within 1.7 km, largest connected part only; shared OSM nodes are the junctions) and puts five stylised Teslas on it (`makeTesla`: one mesh lofted from 14-point cross-sections along the car, with two geometry groups — paint, and dark for sills, windows and glass roof — plus tyres, rims, half-cylinder wheel arches, lamps and mirrors), each starting at the node nearest a different telescope; `moveCars` advances them, picks a random branch at each junction, keeps them 1.1 m right of the centre line and sets height and pitch from `groundAt`. Car materials are plain (not `glowify`'d, so no `aGlow`); the headlight pool is an additive quad sharing `beamMat`, faded in by `applyNight` — not a light. `setFollow(true)` (button `#bFollow`, key F) zooms in behind the next car and then keeps the orbit pivot on it, turning the camera with the car — pivot and heading trail the car with an exponential lag (`follow.yaw`, slower vertically than horizontally) so bumps and junction turns do not jolt the view; `flyTo` cancels it. A click or tap on the canvas without dragging (under 6 px and 400 ms) calls `goTo`, which marches the view ray against `groundAt` (terrain only — buildings are not hit) and flies to 35 % of the distance (60–500 m) with the hit point as the new pivot.

**Amber night glow** has two parts. (1) `glowify` patches every building material to add emissive light scaled by a per-vertex `aGlow` attribute, which `bakeGlow` computes from height above the building base — so every mesh added to a building group must exist before `place()` is called. The strength is a uniform (`uGlowK`), not a shader constant: three.js caches programs by the `onBeforeCompile` source text, so a baked-in constant would be shared by all materials. (2) One `PointLight` per site (`lamp`) sits inside the building to throw a pool onto the ground; these have no shadows and count toward per-fragment light cost on the 500k-triangle terrain.

**Day/night.** `applyNight(n)` is the single place that maps the 0–1 transition onto everything: sky and star uniforms, glow, lamps, fog, hemisphere light, slit colour. There is only one shadow-casting directional light (`sun`); it is the sun for the first half of the transition and jumps to the `MOON` direction for the second half while its intensity is zero. Add new time-dependent effects there rather than in `tick`.

**Weather.** `wx` holds four independent 0–1 values (clouds, rain, snow, fog) that `tick` eases toward `wxTarget`; `applyNight` also reads them, so it is really the one environment update. Rain or snow imply full overcast: they darken the light, thicken the fog, grey the sky dome (`uGray`) and hide the stars (`uClear`). Clouds are a second camera-centred dome drawn between stars and scene — blended, but kept in the opaque queue via `CustomBlending` for the same sorting reason as the stars. Rain (line segments) and snow (points) live in a fixed box that the vertex shader wraps around the camera, so they cost the same wherever the camera is.

**Sky.** A camera-centred dome shader draws the day gradient, the Milky Way with the Magellanic Clouds, and the moon. The Milky Way is procedural (`MW_GLSL`) but is rendered once by `bakeMilkyWay` into a galactic-coordinate (l, b) texture, sqrt-encoded in 8 bits, which the dome samples — computing it per pixel per frame was too slow for phones; stars and galaxies are two separate `Points` clouds built by `buildStars()` from `sky.js`: stars are 6 bytes each (RA uint16, Dec int16, magnitude, B−V colour index; brightest first), galaxies (tinted red in the fragment shader, an artistic choice) are `[RA°, Dec°, major axis arcmin, axis ratio, position angle°, magnitude, name]` and are drawn as ellipses whose on-screen orientation is computed in the vertex shader. The Magellanic Clouds are skipped there (major axis > 250′) because the baked Milky Way texture draws them. Constellation figures are a third object in the same group, a `LineSegments` of faint red additive lines: `LASILLA_SKY.lines` is a flat `[RA°, Dec°, RA°, Dec°]` list per segment, generated from `FIGURES` in `tools/build_sky.py` (hand-written chains of Bayer designations resolved to HYG positions, so no extra data source); the script aborts if a designation does not resolve. Everything is converted to **galactic coordinates** at load and oriented by `orientSky()`, which converts galactic → equatorial → local horizon for the site latitude and the sidereal time `lst` (advancing at 300× real time, 1.25°/s — five sidereal hours per minute). The star material is deliberately non-transparent with additive blending so it sorts into the opaque queue right after the dome (`renderOrder`), otherwise stars draw over buildings. Custom shaders end with `<tonemapping_fragment>` / `<colorspace_fragment>` so they match the ACES-tonemapped scene and the fog colour at the horizon.

**Phones.** `MOBILE` (coarse pointer or small screen) halves the site texture, shadow map and baked Milky Way sizes and caps the pixel ratio at 1.5. Below 720 px wide (or 460 px tall) the CSS hides the hint and credit and turns `#tools` and `#list` into dropdowns opened by two corner buttons, `#bList` top left (`body.list-open`) and `#bMenu` top right (`body.menu-open`); the settings dropdown is a three-column grid (segmented groups span the full width, the plain buttons sit three to a row); only one is open at a time, and tapping the scene or picking a building closes them; every feature must stay reachable from a button because there is no keyboard. Test the phone layout by loading the page in a 390 px wide `<iframe>` — resizing the automation window does not change the viewport. A classic `<script>` after `#loading` writes start-up errors (failed CDN load, no WebGL, exceptions) into the loading overlay.

**Looking up.** `OrbitControls` can only look at the sky by putting the camera below its pivot. `maxPolarAngle` is almost π, and the ground clamp in `tick` handles the rest: when the camera reaches the ground while level or looking up, it lifts camera and pivot together and pulls the pivot to 30 m from the camera, so further tilting turns the view up to the zenith in place. When the camera is clearly above the pivot (normal orbit grazing a hill) only the camera is lifted. The sky is at infinity, so dollying never enlarges it: while the view direction is above the horizon (`dir.y > .12`) `tick` sets `controls.enableZoom = false` and the wheel or a two-finger pinch calls `zoomSky`, which narrows `camera.fov` (`baseFov * skyZoom`, down to 4 %) and scales `rotateSpeed` with it; looking back down eases `skyZoom` to 1. Galaxy sprites scale with the field of view through `uScale`; star points do not. `controls._rotateUp(angle)` is handy for testing this without a mouse.

**Frame loop.** `frame()` only schedules; `tick(dt)` does the work (transition, sky rotation, fly-to animation, WASD movement, `controls.update()`, ground clamp, label projection with overlap culling).

## Conventions

- Dense single-file style: sections separated by `// ---------- name ----------`, short helper lambdas, several statements per line. Match it rather than reformatting.
- Geometry is never shared between meshes (each needs its own `aGlow`).
- Facts shown in the UI (`SPEC[...].info`) are real; keep them accurate. Telescope shapes are stylised, positions and terrain are real.
